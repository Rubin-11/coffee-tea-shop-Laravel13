# Корзина гостя

Гость не пишет в таблицу `baskets`. Корзина лежит в сессии под ключом `cart`.
Так и задумано в [users-baskets-orders.md](../database/users-baskets-orders.md): при будущем
входе Laravel меняет id сессии, но сами данные сессии сохраняются, и их можно перенести
в `baskets`. Этот перенос — этап 6, здесь его нет.

## Что лежит в сессии

```php
['cart' => [12 => 2, 45 => 1]] // product_id => quantity
```

Только id товара и количество. Названия и цены в сессии нет: страница корзины каждый раз
читает их из `products`. Если цену товара изменили, в корзине сразу новая цена. Копия цены
появится позже, в `orders_products`, в момент заказа.

Ноль не хранится. Уменьшение до 0 и кнопка удаления убирают ключ товара. Пустая корзина —
это пустой массив, а не отсутствие ключа после очистки на странице.

Класс — `App\Services\SessionCart`:

- `add` прибавляет количество к уже лежащему товару;
- `set` ставит абсолютное количество (кнопки «−» и «+» присылают его готовым);
- `remove` убирает товар;
- `items` достаёт модели `Product` и считает сумму строки `price * quantity`. Если id
  в сессии есть, а товар мягко удалён, строка выбрасывается и сессия перезаписывается
  без неё;
- `count` — сумма количеств для бейджа в шапке, без запроса в базу;
- `total` — сумма строк.

## Остаток

`products.quantity` — складской остаток. В корзину нельзя положить больше, чем есть.
Проверка в `SessionCart`, а не в Form Request: нужно видеть и новое количество, и то,
что уже лежит в сессии. Если лимит превышен, выбрасывается `ValidationException`,
сессия не меняется, пользователь видит «Нельзя добавить больше, чем есть на складе.»

Остаток при этом не уменьшается. Списание со склада — часть заказа, не корзины.

Мягко удалённый товар не добавляется: `StoreCartRequest` проверяет
`exists` с `whereNull('deleted_at')`, потому что правило `exists` смотрит в таблицу
напрямую и глобальный scope `SoftDeletes` не применяет.

## HTTP

| Метод | URL | Имя | Действие |
|---|---|---|---|
| GET | `/cart` | `cart.index` | страница |
| POST | `/cart` | `cart.store` | добавить (`product_id`, `quantity`) |
| PATCH | `/cart/{product}` | `cart.update` | поставить количество |
| DELETE | `/cart/{product}` | `cart.destroy` | убрать товар |

Кнопка «В корзину» на карточке товара — форма `POST` с `quantity = 1`. Кнопки на
странице корзины — отдельные формы с `@method`, без JavaScript. После изменения
редирект назад.

Шаблон — `resources/views/cart.blade.php`. Старый `resources/views/cart/index.blade.php`
не используется. Промокод, скидка и доставка с макета на страницу не выводятся:
«К оплате» равно сумме товаров. Ссылка «Оформить заказ» ведёт на `/checkout`,
маршрута оформления пока нет.

Счётчик в шапке отдаёт view composer в `AppServiceProvider`: он вызывает `SessionCart::count()`.
Пока корзину не открывали, удалённый товар ещё входит в это число — `count()` не ходит
в базу. Открытие `/cart` чистит такие id через `items()`.

# Отзывы (`reviews`)

Модель: `app/Models/Review.php`. Миграция: `create_reviews_table` (добавлена 2026-10-20).
Статус: схема и связи готовы; форма, контроллер и вывод отзывов на странице товара — в
планах проекта, в коде их пока нет. Сидера и фабрики отзывов тоже пока нет.

| Колонка | Тип | Примечание |
|---|---|---|
| `user_id` | FK → `users.id`, NOT NULL, `cascadeOnDelete` | отзывы пишут только авторизованные |
| `product_id` | FK → `products.id`, `cascadeOnDelete`, индекс | см. «Удаление» ниже |
| `rating` | tinyInteger unsigned, `CHECK (rating BETWEEN 1 AND 5)` | оценка |
| `body` | text, NOT NULL | текст обязателен (решение Сергея 2026-10-20) |

## Ограничения

- **`unique(['user_id', 'product_id'])`** — один отзыв пользователя на товар; повторно
  оценить можно только изменив существующий.
- **`CHECK (rating BETWEEN 1 AND 5)`.** В Postgres нет беззнаковых типов (`unsignedTinyInteger()`
  станет обычным `smallint`), поэтому диапазон держит CHECK, добавленный через
  `DB::statement()` — так же сделано для `baskets.quantity`.
- **`index('product_id')`.** Составной unique начинается с `user_id`, и для запроса «все отзывы
  товара» Postgres его использовать не станет — нужен отдельный индекс.
- **`text`, а не `string`** — отзыв длиннее 255 символов не должен обрезаться или падать.

## Удаление

- Пользователь удалён → его отзывы удаляются (`cascadeOnDelete`, как корзина).
- Товар удаляется мягко (`deleted_at`) → отзывы остаются, строка товара на месте.
- Товар удалён физически (`forceDelete()`, возможен только если его нет в заказах) → отзывы
  уходят каскадом.

## Счётчик `products.reviews_count`

В `Review::booted()` события `created` и `deleted` увеличивают и уменьшают `reviews_count`
через `increment()` / `decrement()` (один атомарный `UPDATE ... SET reviews_count =
reviews_count ± 1`, без гонки «прочитал-записал»). `Product::withTrashed()` — чтобы
счётчик обновлялся и у мягко удалённого товара.

Работает только когда отзыв создаётся/удаляется через модель (`Review::create()`,
`$review->delete()`). Массовое `Review::where(...)->delete()` и сырой SQL события не
вызывают, и счётчик разойдётся. Если нужна гарантия, счётчик можно заменить на
`withCount('reviews')` в запросах и удалить колонку.

Связи: `Review::user()` / `Review::product()` (BelongsTo), `User::reviews()` и
`Product::reviews()` (HasMany). Характеристика «Рейтинг» (1–5) в `properties` — временная
заглушка для фильтров; в перспективе рейтинг товара должен считаться как среднее
`reviews.rating`.
